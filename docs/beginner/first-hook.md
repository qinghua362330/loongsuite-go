# 7. Hands-on: Your First Custom Hook

**Question:** How can you see for yourself that a hook runs before and after the target function, while the original result stays the same?

We'll write a hook for `(*Transport).RoundTrip` in the standard library's `net/http` that only prints logs. The program sends one HTTP request; we build it with plain `go build` and with `otel go build`, then compare the output.

Before starting, [install `otel`](../index.md#installation) and make sure `otel version` works.

## 1. Directory layout

```text
hooklab/
├── go.mod
├── main.go        # business program: sends one HTTP request
├── rule.json      # rule: find RoundTrip
└── rules/
    ├── go.mod
    └── hook.go    # hook: prints one line on entry and one on return
```

## 2. The program

`main.go` starts a local test server, sends it one GET request and prints the result. The OpenTelemetry SDK initialization in the code isn't relevant to this exercise and can be ignored.

```go
package main

import (
	"context"
	"fmt"
	"net/http"
	"net/http/httptest"

	"go.opentelemetry.io/otel"
	"go.opentelemetry.io/otel/sdk/trace"
)

func target(value int) int { return value + 1 }

func main() {
	provider := trace.NewTracerProvider()
	otel.SetTracerProvider(provider)
	defer provider.Shutdown(context.Background())
	_, root := otel.Tracer("guide").Start(context.Background(), "root")
	defer root.End()
	s := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) { w.WriteHeader(http.StatusNoContent) }))
	defer s.Close()
	res, err := http.Get(s.URL)
	if err != nil {
		panic(err)
	}
	defer res.Body.Close()
	fmt.Println("plain-result", target(41), "status", res.StatusCode)
}
```

In `hooklab/`, run:

```bash
go mod init example.com/hooklab
go get go.opentelemetry.io/otel@v1.45.0 go.opentelemetry.io/otel/sdk@v1.45.0
go mod tidy
```

## 3. The rule

`rule.json`:

```json
[
  {
    "ImportPath": "net/http",
    "Function": "RoundTrip",
    "ReceiverType": "\\*Transport",
    "OnEnter": "guideHttpEnter",
    "OnExit": "guideHttpExit",
    "Path": "./rules"
  }
]
```

## 4. The hook

`rules/hook.go`:

```go
package rules

import (
	"fmt"
	"net/http"
	_ "unsafe"

	"github.com/alibaba/loongsuite-go/pkg/api"
)

//go:linkname guideHttpEnter net/http.guideHttpEnter
func guideHttpEnter(call api.CallContext, t *http.Transport, req *http.Request) {
	fmt.Printf("hook-enter method=%s\n", req.Method)
}

//go:linkname guideHttpExit net/http.guideHttpExit
func guideHttpExit(call api.CallContext, res *http.Response, err error) {
	if err != nil {
		fmt.Printf("hook-error=%v\n", err)
		return
	}
	if res != nil {
		fmt.Printf("hook-exit status=%d\n", res.StatusCode)
	}
}
```

Check the three conventions from [Write the Hook Code](../dev/hook.md):

- The first parameter is `api.CallContext`.
- The remaining OnEnter parameters match the target's receiver and parameters: `(t *Transport) RoundTrip(req *Request)`.
- The remaining OnExit parameters match the target's return values: `(*Response, error)`.

`//go:linkname` connects these functions to the call sites generated by the tool, which is why `unsafe` is imported.

`rules/go.mod` declares the `pkg` module the hook depends on. Its version should match the `otel` tool you use; the one below corresponds to v1.15.0:

```text
module guidehook

go 1.25.0

require github.com/alibaba/loongsuite-go/pkg v0.0.0-20260928033626-cac400935add
```

Then run `go mod download github.com/alibaba/loongsuite-go/pkg` in `rules/` to create `go.sum`.

## 5. Compare the two builds

Plain build:

```bash
$ go run .
plain-result 42 status 204
```

Build with `otel`:

```bash
$ otel set -disable= -rule=$PWD/rule.json
$ otel go build -o instrumented .
$ ./instrumented
```

The output contains:

```text
hook-enter method=GET
hook-exit status=204
plain-result 42 status 204
```

Both builds produce the same business result, `plain-result 42 status 204`; the instrumented program prints two extra hook lines. This shows the rule matched `RoundTrip`, the hook ran around the request, and the original result didn't change.

> [!NOTE]
> - `-disable=` keeps all default rules, and `-rule` adds yours on top. Don't use `-disable=all`, which removes rules the tool itself needs. See [CLI Reference](../user/config.md).
> - If no OpenTelemetry Collector is running locally, you may also see export failure logs. They don't affect this exercise. See [OpenTelemetry Settings](../user/sdk-config.md) for exporter settings.

## No hook output?

Check from build time to run time:

1. Did the rule match? Search for `net/http` in `.otel-build/matched.json` and confirm your rule is there. See [Debugging](../hacking/debug.md) for more.
2. Did the build report errors? Check that the hook signatures match the target function.
3. Are you running `./instrumented`, not the plain program from `go run .`?

**Interactive version**: the community-maintained [LoongSuite Go Guide · Labs](https://qinghua362330.github.io/loongsuite-go-guide/#/labs) (Chinese) provides the complete files for this exercise and a script that runs it.
